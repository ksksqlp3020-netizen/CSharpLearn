정적 멤버와 객체 복사

Static Members & Object Copying

“지금까지 만든 적은 몇 마리?”처럼 객체 하나가 아니라 클래스 전체에 속한 값은 static으로 둡니다. 그리고 적을 복제할 때 원본까지 같이 바뀌는 버그를 직접 만들어 보고, 얕은 복사와 깊은 복사로 고칩니다.

문제

객체마다 따로? 모두 함께?

7-1에서 배운 필드는 객체마다 한 벌씩 생깁니다. 그런데 게임에는 두 가지 곤란한 장면이 있습니다.

① 지금까지 만든 적은 몇 마리?

class Enemy{    public int Count;    // 객체마다 따로 생긴다     public Enemy() { Count++; }}

new Enemy()를 세 번 해도 객체마다 자기 Count를 0 → 1로 올릴 뿐입니다. “전체”를 담을 곳이 없습니다.

② 보스를 하나 더 복제하고 싶다

Enemy boss2 = boss;   // 복제했다?boss2.Hp -= 100;      // boss의 Hp도 줄었다!

대입은 객체를 복사하지 않습니다. boss와 boss2는 같은 객체를 가리킵니다.

①은 static으로, ②는 얕은 복사·깊은 복사로 해결합니다.

Console.WriteLine(orc.Count);
> 1   // 객체마다 자기 Count를 0에서 1로 올렸을 뿐

static 필드

static 필드는 클래스에 하나

static을 붙인 필드는 객체가 아니라 클래스에 딱 하나 생깁니다. 객체를 몇 개 만들든 모두 같은 칸을 씁니다. 이런 멤버를 정적 멤버(static member), 객체마다 생기는 멤버를 인스턴스 멤버(instance member)라고 부릅니다.

class Enemy{    public static int Count;   // 클래스에 하나    public string Name;        // 객체마다 하나     public Enemy(string name)    {        Name = name;        Count++;               // 모두 같은 Count    }}// 밖에서는 클래스 이름으로: Enemy.Count

클래스 안에서는 Count, 밖에서는 Enemy.Count처럼 클래스 이름으로 씁니다. 객체를 하나도 만들지 않아도 이미 있습니다(기본값 0).

static 메서드

static 메서드에는 “이 객체”가 없다

static 메서드는 객체 없이 Enemy.PrintCount()처럼 클래스 이름으로 부릅니다. 그래서 안에서는 this가 없고, “어느 적의” Hp인지 알 수 없습니다.

Enemy goblin = new Enemy("고블린"); class Enemy{    public static int Count;    public int Hp = 30;    // ... 생성자     public void TakeDamage(int amount) { Hp -= amount; }     public static void PrintCount()    {        Console.WriteLine($"적 {Count}마리");    }}

어디서 쓰나요?

무엇을 쓰나요?

✓ 컴파일됨

// 인스턴스 메서드 TakeDamage 안 Hp

인스턴스 메서드에는 this(이 객체)가 있어서 Hp는 this.Hp와 같습니다.

16가지 조합을 모두 눌러 보세요. 규칙은 두 줄입니다: 인스턴스 멤버는 객체로, static 멤버는 클래스 이름으로.

정적 클래스 (static class)

객체가 필요 없는 도구 상자

Console.WriteLine(GameMath.Clamp01(1.7f)); // 1Console.WriteLine(Math.Max(3, 7));         // 7 // 객체를 만들 수 없고, static 멤버만 둘 수 있다static class GameMath{    public static float Clamp01(float v)    {        if (v < 0f) return 0f;        if (v > 1f) return 1f;        return v;    }}
  1. 클래스 앞에 static을 붙이면 정적 클래스입니다.
  2. 안의 멤버도 모두 static이어야 합니다. 빼면 오류 CS0708(정적 클래스에는 인스턴스 멤버를 선언할 수 없음).
  3. 클래스 이름으로 바로 씁니다. new GameMath()는 오류 CS0712(정적 클래스의 인스턴스를 만들 수 없음).
이미 써 온 정적 클래스

Console과 Math가 정적 클래스입니다. 그래서 new Console() 없이 Console.WriteLine을 불러 왔던 것입니다.

언제 쓰나

상태(필드)가 필요 없는 계산 모음: 수학 함수, 문자열 도우미, 게임 규칙 계산 등.

  1. static 필드 Count를 선언합니다. 클래스에 하나만 생깁니다.
  2. 생성자에서 Count++. 적이 태어날 때마다 같은 칸이 1씩 올라갑니다.
  3. static 메서드 PrintCount를 만듭니다. 안에서는 static 멤버만 씁니다.
  4. 위쪽에서 적을 만들고 Enemy.PrintCount()를 클래스 이름으로 부릅니다.
  5. Ctrl+F5로 실행합니다.

객체 복사

복사의 세 단계

대입 b = a — 참조만 복사

객체는 하나. 화살표만 하나 더 생깁니다. b로 무엇을 바꾸든 a에 보입니다.

얕은 복사 — 객체는 새로, 안의 참조는 그대로

MemberwiseClone()이 필드 값을 그대로 옮깁니다. Hp는 따로지만 Loot 리스트는 여전히 공유합니다.

깊은 복사 — 가리키는 것까지 새로

리스트처럼 참조로 연결된 객체도 새로 만듭니다. 원본과 아무것도 공유하지 않습니다.

어떤 자료는 대입을 “얕은 복사”라고 부르기도 하지만, .NET에서 얕은 복사는 MemberwiseClone처럼 새 객체를 만들고 필드를 그대로 옮기는 것을 말합니다. 참조가 무엇인지는 복사와 참조: 스택과 힙에서 자세히 다룹니다.

따라 하기 ② · Visual Studio

복사 메서드 두 개 만들기

①의 Enemy에 전리품 리스트와 복사 메서드를 더합니다. 위쪽 문장은 새로 바꿉니다.

  1. Loot 리스트 필드를 추가합니다. 객체마다 리스트 객체를 하나씩 가리킵니다.
  2. 얕은 복사: MemberwiseClone()은 object를 돌려주므로 (Enemy)로 바꿉니다. 생성자를 거치지 않아 Count도 늘지 않습니다.
  3. 깊은 복사: 생성자로 새 객체를 만들고, new List<string>(Loot)로 리스트도 새로 만듭니다.
  4. 복사본에 전리품을 하나씩 넣어 봅니다.
  5. 실행: 얕은 복사본에 넣은 “열쇠”가 보스에게도 들어가 있습니다.

흔한 함정

static과 복사에서 자주 하는 실수

class Enemy{    public int Hp = 30;     public static void PrintHp()    {        Console.WriteLine(Hp);  // ← 오류    }}
CS0120 오류

인스턴스 필드 Hp를 쓰려면 객체 참조가 필요합니다. static 메서드에는 “이 객체”가 없습니다.

고치기

static을 빼서 인스턴스 메서드로 만들거나, 객체를 매개변수로 받습니다: PrintHp(Enemy e) → e.Hp.

Enemy goblin = new Enemy();Console.WriteLine(goblin.Count); // ← 오류 class Enemy{    public static int Count;}
CS0176 오류

static 멤버는 객체(인스턴스 참조)로 쓸 수 없습니다. 형식 이름으로 쓰라는 오류입니다.

고치기

Enemy.Count — static 멤버는 항상 클래스 이름으로.

Enemy a = new Enemy();Enemy b = new Enemy();a.TakeDamage(30);b.PrintHp();             // 70?! b는 안 맞았는데 class Enemy{    static int Hp = 100; // ← 모든 적이 하나를 공유    public void TakeDamage(int d) { Hp -= d; }    public void PrintHp() { Console.WriteLine(Hp); }}
오류 없음 — 그래서 더 위험

컴파일도 되고 실행도 됩니다. 하지만 체력은 객체마다 따로여야 하는 값이라, 한 마리를 때리면 모든 적의 체력이 줄어듭니다.

고치기

“객체마다 다른 값인가, 모두에게 하나인가?”를 먼저 묻습니다. 체력·이름·위치는 인스턴스, 생성된 수·공통 설정은 static.

Enemy copy = boss.ShallowCopy();copy.Loot.Clear();   // 복사본만 비웠는데…Console.WriteLine(boss.Loot.Count); // 0
오류 없음 — 원본의 리스트가 비었다

얕은 복사본의 Loot는 원본과 같은 리스트를 가리킵니다. 복사본의 리스트를 비우면 원본도 비워집니다.

고치기

안에 리스트나 다른 객체가 있으면 깊은 복사로 그것까지 새로 만듭니다: copy.Loot = new List<string>(Loot);

확인 문제

이해했는지 확인해 볼까요?

Q1. public static int Count;가 있고 생성자에서 Count++를 합니다. new Enemy()를 세 번 하면 Enemy.Count는?

정답! 세 객체가 모두 같은 칸을 1씩 올렸습니다.

static 필드는 객체가 없어도 존재하고, 모든 객체가 같은 값을 봅니다.

Q2. static 메서드 안에서 할 수 없는 것은?

정답! static 메서드에는 this가 없습니다 (CS0026).

인스턴스 멤버를 쓰려면 e.Hp처럼 “어느 객체의 것인지”를 직접 알려 줘야 합니다.

Q3. Enemy b = a.ShallowCopy(); b.Hp = 1; b.Loot.Add("돌"); 이후 a는? (ShallowCopy는 MemberwiseClone)

얕은 복사는 “한 겹”만 복사합니다. 안쪽 객체까지 따로 두려면 깊은 복사가 필요합니다.

정리

정적 멤버와 객체 복사 한눈에 보기

  • static 필드는 클래스에 하나, 인스턴스 필드는 객체마다 하나입니다.
  • static 멤버는 Enemy.Count처럼 클래스 이름으로, 인스턴스 멤버는 객체로 씁니다.
  • static 메서드에는 this가 없어서 인스턴스 멤버를 이름만으로 쓸 수 없습니다.
  • static class는 객체를 만들 수 없는 도구 상자입니다 (Math, Console).
  • 대입은 참조만 복사, 얕은 복사는 한 겹만, 깊은 복사는 안쪽 객체까지 새로 만듭니다.
